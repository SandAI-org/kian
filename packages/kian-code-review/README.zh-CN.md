# Kian Review

VS Code 分支／提交／PR审阅工作台。先只展示元数据，点击文件时才打开**一个原生只读 diff**。不用多文件长页面，不启动网页服务，不checkout／stage／commit；已阅状态和私有问题保存在仓库之外。

## 使用

打开源代码管理（`Cmd+Shift+G`），找到 **Kian Review**；也可以从命令面板运行 **Kian Review：显示代码审阅**。默认自动选当前workspace仓库，只列Magi系列、Odin和Magicore；按目录名或Git remote识别，改名的worktree也支持，Quack/PyTorch/Contexts等不进入列表。

顶部改为横向的 **仓库／模式／Base／Compare（或Commit）** 控制栏。点击某个版本只更换这一项；模式菜单可以直接切换。左右版本选择包含分支、标签、近期commit和自定义版本，不重走整套向导；只有主动点仓库按钮才重新选仓库。

底部宽面板采用左侧**提交历史**、中间**变更文件**、右侧**私有问题／详情**切换。两侧都可收起。详情展示完整message、作者、时间、父提交、实际比较基准与worktree路径。各区域独立滚动，窄窗口自动上下排列；开关、滚动、目录展开状态在隐藏／重开后恢复，不启动额外网页服务或端口。

- **分支／PR模式**按钮一键在两个顶端版本和共同祖先口径之间切换。从单提交模式返回时恢复之前的分支对及口径。
- **提交历史**常驻显示SHA、标题、作者和日期，附简单轨迹与merge标识。分支模式只列Compare可达、实际比较基准不可达的提交；点某条即可进入单提交审阅，返回分支模式恢复原先分支对。单提交模式展示固定tip的历史并高亮当前项。搜索仅筛选已加载内容，“加载更早提交”每次追加200条；这是拓扑列表，不是完整分支图。
- **单提交模式**直接使用上次所选commit（首次为当前Compare／HEAD），与第一父提交比较。顶部常驻 **←／→** 按钮切换更早／更新的提交，到头禁用；点 **Commit（选择提交）** 仍可打开原生搜索列表或输入自定义SHA。Base自动取第一父提交，初始提交与空版本比较；主动选择Base会离开自动第一父提交模式，变成普通两版本比较。
- 每个仓库分别记忆分支与提交模式。刷新才重新解析引用，已打开的diff固定到hash；远程分支以最近fetch为准。连接PR后主动刷新可以fetch缺少的对象，不移动本地分支或checkout文件。
- 文件夹默认折叠。**全部展开文件夹／全部折叠文件夹**只操作树，不打开diff或加载源码。目录显示后代文件数和增删行汇总，单个二进制文件带标识；路径搜索同步筛选目录统计。
- 点击文件打开一个原生预览diff。文件行三个小按钮分别复制**对比侧绝对路径**、复制相对路径、打开实体文件，悬停显示说明；原生diff编辑器中仍保留正常右键菜单。
- 同一Git仓库的linked worktree可通过各自分支／commit比较已提交内容。绝对路径优先指向Compare版本实际所在worktree；无匹配worktree时复制当前工作区路径并明确提示。worktree本身可能带未提交改动，路径用于帮agent定位文件，不代表它等于不可变历史源码。删除路径可能已不存在；重命名复制新路径。
- 不比较未提交／未跟踪内容，不比较不共享Git对象的任意两个独立仓库，也不比较两个worktree的脏工作区。

### 文件筛选

**包含文件**与**排除文件**均支持逗号分隔的“或”条件，排除优先；包含留空表示全部。重命名文件同时检查新旧路径，默认不区分大小写：

| 输入 | 含义 |
| --- | --- |
| `attention, comm/` | 路径包含任一片段 |
| `*.py, *.{cu,cpp}` | 任意层级的Python、CUDA或C++文件 |
| `src/**` | `src`路径段下的所有文件 |
| `src/*.py` | 直接位于`src`中的Python文件 |
| 排除 `tests/**, docs/**` | 去掉匹配的测试和文档路径 |

点 **`.*`** 后，两框均使用正则。例如包含`(^|/)(attention|comm)/`，排除`test_.*\.py$`。分组外的逗号仍表示“或”；`{1,3}`、`[a,b]`和`(a,b)`里的逗号保留。正则中匹配逗号本身请写`\,`；普通模式可用引号包住含逗号的文件名。通配符只支持`*`、`**`、`?`、`{a,b}`这个子集，不等于完整VS Code搜索语法。无效条件显示错误，并继续将上一个有效条件用于当前比较；目录统计和已阅栏同步筛选。输入及正则开关在隐藏／重开后恢复，工具栏筛选按钮直接聚焦“包含文件”。

## 文件已阅与私有问题

- 文件前的圆圈标记**已阅**，从未阅树移到折叠的**已阅文件**栏；在那里取消即可恢复。已阅按逻辑仓库／引用对／比较模式区分，不把单个commit的已阅误当成整个PR文件已阅。
- 按每个文件两侧Git对象ID、文件模式、路径及变更类型判断是否过期。只有其他文件更新时保留打钩；该文件的基准或目标变化才撤销，并显示 **Δ**。点击Δ看**自上次已阅以来**的目标变化，点文件名看**完整比较**。若只有基准或元数据变化，目标文本没变，应看完整比较。
- 标记时在扩展私有存储保留确认过的目标blob；force-push／rebase甚至旧commit被Git清理后，仍能显示该增量基线。再次标记推进基线。删除／重命名沿用精确版本身份；这是两个目标快照的diff，不是自动判断人理解过哪些旧hunk。
- 原生diff代码行旁点 **+**，或选择代码后运行**在所选代码行添加私有问题**；**保存到本地**只生成私有prompt，不创建GitHub pending comment。原生私有评论输入框中，**Enter保存，Shift+Enter换行**；中文输入法组词或补全候选出现时，Enter仍先完成输入／补全，不抢先保存。快捷键不影响代码编辑器或其他评论提供方。右侧**私有问题**可打开原位置、编辑、解决／重新打开，并显示已解决项。同一分支审阅与其中的单提交共用问题列表，记录原始side、版本和行号。
- **复制未解决的问题**生成Markdown分点，含绝对路径、从1开始的行号范围、side及版本。解决项保留但不复制；本地resolve不操作GitHub讨论。数据在运行扩展的机器／VS Code用户profile的私有存储，不自动同步到Contexts、Git、其他机器或GitHub。blob缓存和问题均不写入worktree，不自动删除缓存。

## 更新检测与可选GitHub发布

可见的分支审阅每30秒检查本地引用变化，提示刷新并保留当前快照。**未连接PR时，fetch之前无法知道远端push。** 点顶部 **PR** 输入`github.com/.../pull/N`链接，通过VS Code登录GitHub并核对当前仓库remote；连接后检查远端head/base。主动刷新时复用既有Git凭据fetch缺失对象，不移动本地分支、不reset或checkout；隐藏时不轮询，单提交模式继续固定版本。手动另选引用或交换方向会解除PR绑定。

私有问题不自动发布。**提交到GitHub…**先预览正文和目标，再明确确认：当前PR patch内的有效位置发布为行内评论；旧版本、增量旧侧或不在patch的位置，需要确认后作为普通PR评论发布。不发approve／request-changes；确认期间PR变化则要求先刷新。写入失败保留问题，重试会通过隐藏的问题ID查找已成功但丢失响应的评论，避免重复发布。发布回执仍在本地。网络复用VS Code的`http.proxy`或标准代理环境变量，保留TLS校验；token通过VS Code认证读取，不写入审阅JSON或命令参数。

## 语言支持与边界

历史文件复用 Git 内置扩展的 `git:` 文档和原生 diff。继续沿用语法高亮及现有语言支持；Pylance 虚拟文档能力取决于版本／设置，跨文件跳转可能使用当前工作区，不能保证历史语义环境隔离。

二进制沿用 VS Code 原生 diff 行为，不转为自定义文本；子模块不递归展开比较。单个超大文件仍可能慢，这里减少的是同时创建多个 diff 的负担。Git 每次执行超时30秒，元数据上限32MiB；只读命令超时后自动重试一次，无效引用或其他Git错误不重试。失败保留原比较并恢复菜单的实际模式；Kian Review输出通道记录仓库、命令、耗时、退出码／信号、超时状态和尝试次数。只支持受信任且实际落盘的 Git workspace；不使用实验接口。

## 开发与打包

无运行时 npm 依赖、无编译步骤。执行 `node --test test/git.test.js`。`node test/create-fixture.js` 创建临时Magi仓库及linked feature worktree，输出JSON包含路径。`test/extension-host.js` 验证真实Webview渲染、筛选／折叠／详情开关、提交选择与导航、消息校验、单文件按需打开、worktree路径／剪贴板、状态恢复、过期请求防护及Git状态不变。DOM probe仅注入隔离测试Webview，不进入安装包；使用独立user-data／extensions目录运行。

在本包执行 `npm run package:vsix`，使用固定版本的打包工具，产物统一写入 `dist/kian-code-review-<version>.vsix`。这是 Git 忽略的固定本地产物目录，不再放 Downloads。通过“扩展：从 VSIX 安装”安装。SSH／Dev Container 必须安装在远程环境，Git 与文件读取才会发生在对应机器；若提示 Reload，只重载该窗口。

源码在 Kian 维护；VSIX 和原始测试日志不入 Git。
